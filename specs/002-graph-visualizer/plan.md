# Implementation Plan: Interactive Graph Visualizer

**Branch**: `002-graph-visualizer` | **Date**: 2026-04-26 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/002-graph-visualizer/spec.md`

---

## Summary

Build an interactive browser-based visualization for the KitGraph JSON produced by the Core Analysis Engine. A D3 v7 force-directed graph renders all classified kit files as draggable nodes (circle + category icon + color) connected by directional animated edges (color + dash pattern by relationship type) on a dark canvas. Two delivery modes: `repoviz serve <graph.json>` (local server + browser launch) and `repoviz bundle <graph.json>` (single self-contained HTML file). Features: zoom/pan, hover tooltip, click sidebar, harness/category filter, text search — all applied via unified opacity-based fading without layout disruption.

---

## Technical Context

**Language/Version**: TypeScript 5.x / Node.js 20 LTS (CLI + server) + HTML5/CSS3/SVG (browser)
**Primary Dependencies**:
- `d3` v7 — force simulation, zoom, drag, transitions, SVG selections
- `esbuild` — bundle browser TypeScript to single minified JS (dev dependency)
- `open` — cross-platform browser launch from Node.js CLI
**Storage**: Filesystem only — reads `graph.json`, writes `graph.html`
**Testing**: Vitest (unit tests for data transformations, filter logic, CLI commands); browser visual tests via Playwright or manual fixture validation
**Target Platform**: Desktop browser (Chrome, Firefox, Safari, Edge — latest 2 major versions); CLI on Node.js 20 LTS, cross-platform (Windows, macOS, Linux)
**Project Type**: CLI extension (new subcommands added to existing `repoviz` CLI) + browser app (compiled to single inline bundle)
**Performance Goals**:
- 50 nodes + 30 edges: interactive within 3 seconds of browser open (SC-001)
- Filter/search state changes: < 200ms (SC-005)
- `repoviz serve` opens browser: < 2 seconds (SC-007)
- Bundle size (D3 + app code + CSS): < 500KB uncompressed
**Constraints**:
- Zero network calls from the browser visualizer — all assets inline, no CDN
- `file://` protocol compatible for the HTML bundle
- Force simulation settles and stops consuming CPU within ~3 seconds (alpha decay)
- No authentication, no telemetry, no external services
**Scale/Scope**: Up to 500 nodes; 7 node categories; 6 edge relationship types; 6+ harnesses

**Structure Decision**: The viewer (`src/viewer/`) is compiled separately by esbuild into a browser bundle. The server and bundler (`src/server/`, `src/bundler/`) run in Node.js and are compiled by `tsc` along with the rest of the CLI. The two compile targets share the `KitGraph` type definitions from `src/output/types.ts` (already in the engine).

## Implementation Phases

### Phase A — Core Rendering (US1 — MVP)

1. Add `esbuild` dev dependency; create `scripts/build-viewer.ts` to compile `src/viewer/` → `dist/viewer.bundle.js`
2. Create `viewer/template.html` — dark canvas HTML shell with SVG container, CSS variables for dark theme, placeholder `<!-- DATA_INJECTION_POINT -->`
3. Implement `src/viewer/theme.ts` — `CategoryVisual` and `EdgeVisual` constants with all colors, icons, dash patterns
4. Implement `src/viewer/graph.ts` — D3 force simulation: `forceCenter`, `forceManyBody` (repulsion), `forceLink` (edge spring), `forceCollide` (node separation); tick handler updates SVG positions
5. Implement `src/viewer/nodes.ts` — SVG `<g>` per node with: circle, icon path, truncated label; bind data from `window.__REPOVIZ_DATA__.nodes`
6. Implement `src/viewer/edges.ts` — SVG `<path>` per edge with arrow markers; CSS pulse animation via `stroke-dashoffset`; curved offset for multi-edges
7. Implement `src/viewer/index.ts` — loads `window.__REPOVIZ_DATA__`, validates shape, initializes graph; error overlay if invalid
8. Implement `src/server/serve.ts` — Node.js `http` server; injects graph data into template; binds random port; prints URL to stderr
9. Implement `src/bundler/bundle.ts` — reads template.html, inlines viewer bundle JS, inlines graph data, writes single HTML file
10. Extend `src/cli/index.ts` — add `serve` and `bundle` subcommands with argument parsing
11. Add D3 zoom + pan to `src/viewer/graph.ts`; add drag behavior to nodes
12. Add "Reset Layout" button to template.html; wire to `graph.ts` alpha restart
13. Add summary bar to template.html — total nodes, edges, harnesses, repo path
14. Write unit tests for bundler and CLI argument parsing
15. Validate end-to-end: `repoviz bundle tests/fixtures/claude-workspace/graph.json --output /tmp/test.html` → open in browser → all 7 nodes visible

### Phase B — Node + Edge Inspection (US2)

1. Implement `src/viewer/tooltip.ts` — floating `<div>` positioned near cursor; shows node data on hover; edge data on edge hover
2. Implement `src/viewer/sidebar.ts` — slide-in right panel; node metadata fields; grouped relationship list (outgoing + incoming); "navigate to" links for related nodes
3. Wire hover events on nodes → tooltip; click events → sidebar
4. Wire hover events on edges → edge tooltip
5. Implement "navigate to related node": pan + zoom graph to center on target; apply highlight ring
6. Write unit tests for sidebar data assembly (relationship grouping by type)
7. Validate: click on `researcher.md` node in fixture → sidebar shows name, description, all relationships correctly

### Phase C — Filter, Search, Legend (US3)

1. Implement `src/viewer/filters.ts` — `FilterState` + `visibleNodeIds` computation (set intersection of harness + category + search)
2. Implement harness filter panel in template.html — checkbox/toggle per detected harness
3. Implement category filter panel in template.html — checkbox/toggle per category present in graph
4. Implement `src/viewer/search.ts` — text input handler; updates `FilterState.searchQuery`
5. Wire FilterState changes to D3 opacity updates on nodes and edges (CSS transition)
6. Add "Clear Filters" button; implement legend panel (`src/viewer/legend.ts`)
7. Write unit tests for `FilterState` computation with combined filters
8. Validate: multi-harness fixture → filter by claude-code → github-copilot nodes fade; search "researcher" → only researcher node visible; both filters active simultaneously

### Phase D — Standalone Bundle + Polish (US4 + cross-cutting)

1. Verify `repoviz bundle` produces valid offline HTML (no external deps)
2. Validate `file://` protocol in Chrome, Firefox, Safari
3. Implement all edge case handlers: empty graph (empty state message), single node (centered), malformed JSON (error overlay), unresolved edges (visual distinction + tooltip)
4. Write integration test: `repoviz bundle` → HTML file → Playwright headless browser → assert node count matches fixture
5. Performance test: 500-node synthetic graph → bundle → browser open → interactive in < 3s
6. Final visual polish: animation tuning, legend layout, sidebar transitions
7. Update `README.md` with `repoviz serve` and `repoviz bundle` documentation

## Key Design Decisions (from research.md)

- **SVG via D3 v7**: Per-element event handling + CSS transitions; Canvas rejected (no per-element CSS opacity)
- **Single-file inline bundle**: `file://` protocol requires inlined data; no CDN dependency
- **esbuild**: Fastest bundler for this output; D3 + app code < 500KB
- **Node.js `http` built-in for serve**: Zero extra production dependencies; random port avoids conflicts; Ctrl+C to exit (standard pattern)
- **Inline SVG path icons**: No font/CDN dependency; scales with node radius; category-unique symbols
- **Unified opacity fading**: All three filter dimensions (harness, category, search) produce one `visibleNodeIds` set; single opacity pass per change → <200ms SC-005
- **`stroke-dashoffset` pulse animation**: GPU-accelerated; `animation-play-state: paused` for faded edges
